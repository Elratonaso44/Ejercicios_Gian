Lección 1 · API de profesores

El viaje del JSON

Antes de escribir Angular, vamos a entender el contrato que ya ofrece tu servidor.

1. ¿Qué hace cada parte?

  1. Angular se ejecuta en el navegador y pide información.
  2. Express recibe la petición en una ruta.
  3. El controlador consulta el modelo, que obtiene los datos de MySQL.
  4. El servidor devuelve una respuesta JSON.
  5. Angular lee el JSON y lo convierte en elementos visibles.

2. La primera ruta

En server.js se monta el router con el prefijo /profesores. En routes/profesoresRoutes.js se define GET /listar. Juntas, esas dos partes forman:

GET http://localhost:3000/profesores/listar

La consulta es pública: no necesita token. El controlador responde con una forma parecida a esta:

{
  "mensaje": "consulta profesores",
  "data": [
    { "nombre": "Ana", "apellido": "Díaz", "edad": 35, "materia": "Matemática" }
  ]
}
Idea clave: la lista está dentro de data. Cuando Angular la reciba, usaremos respuesta.data; la respuesta completa no es directamente el array.

3. JavaScript primero, tipos después

En TypeScript describiremos la forma de un profesor. Una interfaz no crea datos ni consulta al servidor; solo ayuda a que el editor y el compilador detecten errores mientras programamos.

interface Profesor {
  nombre: string;
  apellido: string;
  edad: number | null;
  materia: string;
}

Esto se parece a documentar el objeto que ya manda tu entidad Profesor en entities/Profesor.js. La respuesta actual observada no incluye id; para editar o borrar necesitaremos que el backend lo incluya.

4. Comprobación rápida

Sin mirar arriba: ¿qué propiedad contiene el array de profesores que devuelve la API?

Tu siguiente paso

Cuando el servidor esté funcionando, abrí http://localhost:3000/profesores/listar en el navegador. Mirá el JSON y comprobá dónde aparece la lista. Todavía no hace falta cambiar nada.
